# Farma v1: plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Cel:** grywalna wersja 1 izometrycznej, pikselowej gry o rozbudowie farmy dla 9-latka, działająca w przeglądarce i jako PWA na iPadzie.

**Architektura:** cała logika gry siedzi w czystym TypeScripcie w `src/core/` (bez Phasera, bez DOM), testowanym jednostkowo w Vitest. Stan to zwykły serializowalny obiekt `GameState`, a akcje i `tick()` mutują go w miejscu. Renderowanie mapy izometrycznej robi Phaser 3 (`src/game/`), interfejs (HUD, przyciski, panele) to nakładka DOM/CSS (`src/ui/`). Grafika to pixel-mapy w TS (`src/art/`), zamieniane na tekstury przy starcie, z kluczami podmienialnymi na PNG (plan B: gotowe paczki).

**Stack:** TypeScript 5, Vite 5, Phaser 3.80, Vitest 2, vite-plugin-pwa 0.20, tsx (skrypty), pngjs (ikony PWA).

**Spec:** `docs/superpowers/specs/2026-11-15-farma-design.md`. Wszystkie liczby oznaczone tam [do strojenia] trzymamy w jednym pliku `src/core/config.ts`.

## Ograniczenia globalne

- Wszystkie teksty w grze są po polsku, krótkie (etykieta lub kilka słów, bez zdań). Teksty żyją tylko w `src/ui/copy.ts`.
- Sterowanie tylko klik/dotyk. Żadnych skrótów klawiszowych ani hovera jako jedynej drogi do funkcji.
- Minimalny cel dotykowy to 48×48 px CSS.
- Docelowe urządzenie: iPad Safari, gra dodana do ekranu głównego (PWA, offline).
- Zwierzęta nigdy nie umierają i nic nie przepada bezpowrotnie.
- Czas gry płynie tylko, gdy karta jest widoczna (`visibilitychange` pauzuje grę). Jeden krok `tick` to najwyżej `MAX_DT_MS = 1000`.
- Pora roku trwa 60 min czasu gry, przejście 5 min.
- Zapis: `localStorage`, klucz `farma.save.v1`, autozapis co 5 s i po każdej udanej akcji.
- Debug przez parametry URL: `?speed=N` (mnożnik czasu, 1–100), `?seed=N`, `?debug=1` (+1000 monet, przycisk +level).
- `src/core/**` nie importuje `phaser` ani nie używa `window`/`document`.

## Na co uważać przy review

1. **iPad zawiesza lub zamyka kartę w trakcie gry.** Po powrocie czas nie skacze (nie przybywa godzina wzrostu), a stan sprzed zamknięcia jest zapisany. Test: `tick` z ogromnym `dt` przesuwa czas najwyżej o `MAX_DT_MS` (Zadanie 3). Kontroler zapisuje stan na `visibilitychange` (Zadanie 9).
2. **Uszkodzony lub obcy plik zapisu (localStorage albo „Wczytaj kopię”).** Gra startuje normalnie (uszkodzony zapis odkłada na bok), a import złego pliku nie nadpisuje obecnej farmy. Testy w Zadaniu 9.
3. **Przeciąganie palcem po tych samych polach i podwójne stuknięcia.** Nie ma podwójnych opłat ani podwójnych zbiorów: akcja na nieodpowiednim polu zwraca błąd bez zmiany stanu. Testy w Zadaniach 4 i 6.
4. **Brak monet, zła pora roku, za niski level.** Akcja jest odrzucana atomowo (zero zmian w stanie), a przycisk w UI jest wyszarzony. Testy `expectUnchanged` w Zadaniach 4–7.
5. **Pełna zagroda.** Nie da się kupić zwierzęcia ponad pojemność, nie rodzą się młode, a rozbudowa (lvl 9) podnosi limit. Testy w Zadaniu 6.

```ts
// types.ts
export type CropId = 'wheat' | 'carrot' | 'corn' | 'pumpkin';
export type ProductId = 'egg' | 'milk';
export type ItemId = CropId | ProductId;
export type SpeciesId = 'chicken' | 'cow' | 'horse';
export type BreedId = 'pony' | 'arabian' | 'friesian';
export type BuildingKind = 'coop' | 'barn' | 'stable';
export type Season = 'spring' | 'summer' | 'autumn' | 'winter';
export type WeatherKind = 'sun' | 'rain' | 'heat' | 'snow';

export interface Field { id: string; x: number; y: number; crop: CropId | null; growthMs: number; watered: boolean; }
export interface Building { id: string; kind: BuildingKind; x: number; y: number; upgraded: boolean; trough: number; } // trough = punkty paszy; zajmuje 2×2 od (x,y)
export interface Animal {
  id: string; species: SpeciesId; breed: BreedId | null; buildingId: string;
  youngMsLeft: number;      // >0 = młode, nie produkuje
  sick: boolean;
  cycleMs: number;          // postęp bieżącego cyklu; -1 = cykl nie wystartował (czeka na paszę)
  productReady: boolean;    // tylko chicken/cow
  treat: boolean;           // smakołyk aktywny do końca cyklu
  bornOnFarm: boolean;
}
export interface GameState {
  version: 1; timeMs: number; coins: number; xp: number; level: number;
  storage: Record<ItemId, number>;
  freeSeeds: Record<CropId, number>;
  parcels: boolean[];                 // 16 działek 4×4, indeks = py*4+px
  fields: Field[]; buildings: Building[]; animals: Animal[];
  weather: { kind: WeatherKind; untilMs: number };
  hasTractor: boolean;
  ownedBreeds: BreedId[];             // kolekcja
  nextId: number;
  safetyNetAtMs: number;              // następne sprawdzenie
  lastSeason: Season;                 // do zdarzenia seasonChanged
}
export type Reason = 'no-money' | 'locked' | 'out-of-season' | 'occupied' | 'not-ready' | 'full'
  | 'no-feed' | 'invalid' | 'sick' | 'young' | 'no-item';
export type ActionResult = { ok: true; n?: number } | { ok: false; reason: Reason };
export type GameEvent =
  | { type: 'levelUp'; level: number }
  | { type: 'born'; animalId: string }
  | { type: 'sick'; animalId: string }
  | { type: 'seasonChanged'; season: Season }
  | { type: 'weatherChanged'; kind: WeatherKind }
  | { type: 'safetyNet' }
  | { type: 'gain'; x: number; y: number; coins?: number; xp?: number; item?: ItemId; qty?: number };
export interface Rng { next(): number } // [0,1)
export interface Ctx { rng: Rng; events: GameEvent[] }
```

**Interfejsy:**
- `getSeasonInfo(timeMs: number): { season: Season; inTransition: boolean; next: Season; transitionProgress: number; label: string }`. Rok to 4×(60+5) min. Kolejność: wiosna(60) → „Późna wiosna”(5) → lato → „Wczesna jesień” → jesień → „Przedzimie” → zima → „Roztopy” → wiosna. Podczas przejścia `season` to pora **poprzednia** (rządzi sadzeniem i pogodą), `next` to nadchodząca, a `transitionProgress` rośnie od 0 do 1. Etykiety głównych pór: „Wiosna”, „Lato”, „Jesień”, „Zima”.
- `rollWeather(season: Season, rng: Rng): WeatherKind` (z `WEATHER_TABLE`, skumulowane progi).
- `updateWeather(s: GameState, ctx: Ctx): void`: gdy `timeMs >= weather.untilMs`, losuje nową pogodę i czas trwania oraz emituje `weatherChanged`, jeśli rodzaj się zmienił. Zmiana pory na zimę wymusza nowe losowanie (śnieg nie może padać latem i odwrotnie).
- `tick(s: GameState, ctx: Ctx, dtMs: number): void`: `dt = clamp(dtMs, 0, MAX_DT_MS)`, `timeMs += dt`, emituje `seasonChanged` przy zmianie `season`, wywołuje `updateWeather`. Kolejne zadania dopisują tu swoje `updateX(s, ctx, dt)` w kolejności: crops → animals → safetyNet.
